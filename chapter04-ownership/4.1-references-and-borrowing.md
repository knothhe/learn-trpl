# References and Borrowing

原文：https://rust-book.cs.brown.edu/ch04-02-references-and-borrowing.html

这一节讲 Rust 里非常核心的一件事：如何在不转移所有权的情况下访问数据。

关键词：

- `&T`：不可变引用，也叫 shared reference
- `&mut T`：可变引用，也叫 mutable/unique reference
- borrow：借用
- dereference：解引用，`*`
- borrow checker：借用检查器
- lifetime：引用的生命周期

## 为什么需要引用

前一节讲过 ownership 和 move。比如：

```rust
fn greet(g1: String, g2: String) {
    println!("{} {}", g1, g2);
}

fn main() {
    let m1 = String::from("Hello");
    let m2 = String::from("world");

    greet(m1, m2);

    println!("{} {}", m1, m2); // error
}
```

`greet(m1, m2)` 会把 `m1` 和 `m2` 的所有权移动到 `greet` 里面。
函数结束后，两个 `String` 被释放，所以 `main` 里不能再使用它们。

如果一个函数只是想读取字符串，却必须拿走所有权，这会非常不方便。
Rust 提供引用来解决这个问题：

```rust
fn greet(g1: &String, g2: &String) {
    println!("{} {}", g1, g2);
}

fn main() {
    let m1 = String::from("Hello");
    let m2 = String::from("world");

    greet(&m1, &m2);

    println!("{} {}", m1, m2); // ok
}
```

对比：

```rust
greet(m1);  // move，所有权转移
greet(&m1); // borrow，借用
```

引用是 non-owning pointer：它指向数据，但不拥有数据。

## 引用不负责释放数据

```rust
let s = String::from("hello");
let r = &s;
```

这里：

- `s` 拥有 `String`。
- `r` 只是指向 `s` 的引用。
- `r` 离开作用域时，不会释放字符串。
- 只有拥有者 `s` 离开作用域时，堆上的字符串才会被释放。

内存关系可以粗略理解成：

```text
r -> s -> heap data "hello"
```

`r` 不拥有 `s`，也不拥有 heap data。

## 解引用

引用本身是一个指针值。要访问它指向的数据，可以使用 `*`：

```rust
fn main() {
    let x = 5;
    let r = &x;

    println!("{}", *r);
}
```

`r` 的类型是 `&i32`，`*r` 的类型是 `i32`。

不过 Rust 经常会自动帮你借用或解引用，尤其是方法调用：

```rust
fn main() {
    let x: Box<i32> = Box::new(-1);

    let x_abs1 = i32::abs(*x); // 显式解引用
    let x_abs2 = x.abs();      // 方法调用时自动解引用

    assert_eq!(x_abs1, x_abs2);
}
```

多层指针也可以自动解引用：

```rust
fn main() {
    let x: Box<i32> = Box::new(-1);
    let r: &Box<i32> = &x;

    let r_abs1 = i32::abs(**r); // 显式解引用两次
    let r_abs2 = r.abs();       // 自动解引用两次

    assert_eq!(r_abs1, r_abs2);
}
```

方法调用也可能自动借用：

```rust
fn main() {
    let s = String::from("Hello");

    let len1 = str::len(&s);
    let len2 = s.len();

    assert_eq!(len1, len2);
}
```

重要心智模型：

- `&x`：创建引用。
- `*r`：访问引用指向的数据。
- 方法调用语法经常会自动插入借用或解引用。

## Pointer Safety Principle

这一节最重要的原则：

```text
data should never be aliased and mutated at the same time
```

也就是：

```text
数据不能在被别名访问的同时被修改。
```

aliasing 指多个变量能访问同一份数据。

单独 aliasing 通常没问题：

```rust
fn main() {
    let s = String::from("hello");
    let r1 = &s;
    let r2 = &s;

    println!("{} {}", r1, r2);
}
```

单独 mutation 也没问题：

```rust
fn main() {
    let mut s = String::from("hello");
    s.push_str(" world");
}
```

危险的是 aliasing 和 mutation 同时发生。

## Vec 的例子

```rust
fn main() {
    let mut v = vec![1, 2, 3];

    let num = &v[2];

    v.push(4);

    println!("{}", num);
}
```

这段代码不能编译。

原因是 `Vec` 的元素存在 heap 上。`v.push(4)` 时，如果容量不够，`Vec` 可能会：

1. 申请一块更大的新内存。
2. 把旧元素复制到新内存。
3. 释放旧内存。

而 `num` 原本指向旧数组里的第三个元素。如果 `push` 触发重新分配，`num` 就会指向已经失效的内存。

Rust 会阻止这种情况：

```text
cannot borrow `v` as mutable because it is also borrowed as immutable
```

正确写法：

```rust
fn main() {
    let mut v = vec![1, 2, 3];

    let num = &v[2];
    println!("{}", num);

    v.push(4);
}
```

`num` 最后一次使用发生在 `v.push(4)` 之前，所以借用已经结束。

## 权限模型：R、W、O

Brown 版用权限模型解释 borrow checker。

变量对数据可能有三种权限：

- `R`：Read，可以读。
- `W`：Write，可以写。
- `O`：Own，可以拥有、移动、drop。

普通变量：

```rust
let s = String::from("hello");
```

`s` 有：

```text
R O
```

可变变量：

```rust
let mut s = String::from("hello");
```

`s` 有：

```text
R W O
```

这些权限只存在于编译器分析阶段，不存在于运行时。

## 不可变引用会临时拿走 W 和 O

```rust
fn main() {
    let mut v = vec![1, 2, 3];

    let num = &v[2];

    println!("{}", num);

    v.push(4);
}
```

创建 `v` 之后：

```text
v: R W O
```

创建不可变引用：

```rust
let num = &v[2];
```

借用期间：

```text
v: R
num: R O
*num: R
```

意思是：

- `v` 还能读。
- `v` 不能写。
- `v` 不能 move 或 drop。
- `num` 是引用变量。
- `*num` 指向的数据可以被读。

所以借用期间可以读：

```rust
println!("{}", v[0]);
println!("{}", num);
```

但不能写：

```rust
v.push(4); // error if num will be used later
```

也不能 drop：

```rust
drop(v); // error if num will be used later
```

## 引用的生命周期

引用的 lifetime 是从引用创建开始，到最后一次使用结束。

现代 Rust 使用 non-lexical lifetimes，所以引用不一定活到作用域结束。

可以编译：

```rust
fn main() {
    let mut s = String::from("hello");

    let r = &s;
    println!("{}", r);

    s.push_str(" world");
}
```

`r` 最后一次使用在 `println!`，所以之后可以修改 `s`。

不能编译：

```rust
fn main() {
    let mut s = String::from("hello");

    let r = &s;

    s.push_str(" world");

    println!("{}", r);
}
```

因为 `r` 在修改之后还要使用。也就是说，修改发生时 `r` 仍然活着。

## 可变引用

可变引用使用 `&mut` 创建：

```rust
fn main() {
    let mut x = 5;

    let r = &mut x;
    *r += 1;

    println!("{}", x);
}
```

规则：

```text
同一时间，要么有多个不可变引用，要么只有一个可变引用。
```

多个不可变引用可以：

```rust
fn main() {
    let s = String::from("hello");

    let r1 = &s;
    let r2 = &s;

    println!("{} {}", r1, r2);
}
```

多个可变引用不可以：

```rust
fn main() {
    let mut s = String::from("hello");

    let r1 = &mut s;
    let r2 = &mut s;

    println!("{} {}", r1, r2);
}
```

不可变引用和可变引用也不能同时存在：

```rust
fn main() {
    let mut s = String::from("hello");

    let r1 = &s;
    let r2 = &mut s;

    println!("{} {}", r1, r2);
}
```

## 为什么可变引用必须唯一

`&mut T` 表示 unique access。

当存在可变引用时，它应该是这段时间内访问该数据的唯一入口。

否则就可能出现两个地方同时修改同一份数据：

```rust
fn main() {
    let mut v = vec![1, 2, 3];

    let a = &mut v;
    let b = &mut v;

    a.push(4);
    b.push(5);
}
```

Rust 禁止这种代码。

## `let mut r` 和 `&mut T` 不是一回事

这点很容易混淆。

```rust
fn main() {
    let x = 5;
    let y = 10;

    let mut r = &x;
    r = &y;

    println!("{}", r);
}
```

`mut r` 表示变量 `r` 自己可以重新绑定到别的引用。

但它指向的数据不能改，因为 `r` 的类型是 `&i32`。

这个不行：

```rust
fn main() {
    let mut x = 5;

    let mut r = &x;
    *r += 1; // error
}
```

如果想修改指向的数据，需要 `&mut`：

```rust
fn main() {
    let mut x = 5;

    let r = &mut x;
    *r += 1;
}
```

如果既想修改指向的数据，又想让引用变量本身重新指向别处：

```rust
fn main() {
    let mut x = 5;
    let mut y = 10;

    let mut r = &mut x;
    *r += 1;

    r = &mut y;
    *r += 1;
}
```

区别：

- `mut r`：`r` 这个变量可以变。
- `&mut x`：可以通过引用修改 `x`。

## 可变引用可以临时降级为不可变引用

```rust
fn main() {
    let mut x = 5;

    let r = &mut x;
    let r2 = &*r;

    println!("{} {}", r, r2);
}
```

`r` 是 `&mut i32`。
`r2` 是 `&i32`。

`&*r` 的意思是：

1. `*r`：访问 `r` 指向的数据。
2. `&*r`：再创建一个不可变引用。

在 `r2` 活着的时候，不能通过 `r` 写入：

```rust
fn main() {
    let mut x = 5;

    let r = &mut x;
    let r2 = &*r;

    *r += 1; // error
    println!("{}", r2);
}
```

但如果 `r2` 最后一次使用已经结束，就可以继续写：

```rust
fn main() {
    let mut x = 5;

    let r = &mut x;
    let r2 = &*r;

    println!("{}", r2);

    *r += 1;
}
```

## 数据必须比引用活得更久

引用不能比它指向的数据活得更久。

错误例子：

```rust
fn main() {
    let r;

    {
        let x = 5;
        r = &x;
    }

    println!("{}", r);
}
```

`x` 在内部作用域结束时被销毁，但 `r` 还想继续指向它。
这会产生 dangling reference，所以 Rust 禁止。

函数返回局部变量引用也不行：

```rust
fn return_ref() -> &String {
    let s = String::from("hello");
    &s
}
```

`s` 是函数内部的局部变量。函数返回后，`s` 被释放，返回的引用会悬空。

正确做法是返回所有权：

```rust
fn return_string() -> String {
    let s = String::from("hello");
    s
}
```

或者返回来自输入参数的引用：

```rust
fn first(strings: &Vec<String>) -> &String {
    &strings[0]
}
```

这里返回的引用指向调用者传进来的数据。

## 多个输入引用和 lifetime 参数

下面这个函数可能报错：

```rust
fn first_or(strings: &Vec<String>, default: &String) -> &String {
    if strings.len() > 0 {
        &strings[0]
    } else {
        default
    }
}
```

原因是函数有两个输入引用：

```rust
strings: &Vec<String>
default: &String
```

返回值也是引用：

```rust
&String
```

Rust 需要知道返回的引用和哪个输入引用有关：

- 可能来自 `strings`。
- 可能来自 `default`。

这会影响调用者是否可以安全使用返回值。

例如：

```rust
fn main() {
    let strings = vec![];
    let default = String::from("default");

    let s = first_or(&strings, &default);

    drop(default);

    println!("{}", s);
}
```

如果 `s` 实际引用的是 `default`，那么 `drop(default)` 后 `s` 就失效了。

Rust 后面会用 lifetime 参数描述这种关系：

```rust
fn first_or<'a>(strings: &'a Vec<String>, default: &'a String) -> &'a String {
    if strings.len() > 0 {
        &strings[0]
    } else {
        default
    }
}
```

这一章不需要完全掌握 lifetime 参数，只需要知道：

- 函数内部临时引用可以靠 borrow checker 分析。
- 函数输入和输出引用之间的关系，有时需要 lifetime 参数说明。

## 常见错误判断方法

遇到借用错误时，可以按这个顺序检查。

第一，是否发生了 move：

```rust
let s = String::from("hello");
let t = s;
println!("{}", s); // error
```

第二，是否在引用仍然活着时修改原数据：

```rust
let mut v = vec![1, 2, 3];
let x = &v[0];
v.push(4);
println!("{}", x); // error
```

第三，是否同时存在不可变引用和可变引用：

```rust
let mut s = String::from("hello");

let r1 = &s;
let r2 = &mut s;

println!("{}", r1); // error
```

第四，是否同时存在多个可变引用：

```rust
let mut s = String::from("hello");

let r1 = &mut s;
let r2 = &mut s;

println!("{} {}", r1, r2); // error
```

第五，是否返回了局部变量的引用：

```rust
fn bad() -> &String {
    let s = String::from("hello");
    &s
}
```

## 本节总结

引用让你可以在不转移所有权的情况下访问数据。

核心规则：

- `&T` 可以读，不能写。
- `&mut T` 可以写，但必须独占。
- 同一时间可以有多个不可变引用。
- 同一时间只能有一个可变引用。
- 不可变引用和可变引用不能同时作用在同一份数据上。
- 引用不能比它指向的数据活得更久。
- 引用最后一次使用后，借用结束，权限归还。

一句话：

```text
many readers or one writer
```

要么多个读者，要么一个写者。
